# Plan: `rating` component (star rating input)

## Architecture — Base UI RadioGroup as substrate

No rating primitive exists in Base UI 1.6.0 (verified). `RadioGroup` gives us exactly what a rating needs: scalar `value`/`defaultValue`/`onValueChange` (generic `Value` unconstrained → numbers fine), roving tabindex + arrow/Home/End keyboard (radiogroup = the WAI-ARIA-recommended rating pattern), `disabled`/`readOnly`/`name`/`form` + hidden input (form-submittable), and `FieldRootState` integration for `aria-invalid` styling. `rating.tsx` (~140 lines) is a styled composition in the house compound style:

- **`Rating`** (root) — wraps `RadioGroup` from `@coss/radio-group`. Props beyond the passthrough:
  - `count?: number = 5` — renders N stars when no children are passed (the ergonomic default; consumers don't hand-write five items)
  - `size?: "sm" | "default" | "lg"` — `data-size` convention, children style via `in-data-[size=sm]:` (number-field precedent)
  - `allowClear?: boolean = false` — clicking the selected value selects `undefined`
  - `value`/`defaultValue`: `number | undefined`; `onValueChange?: (value: number | undefined) => void`
  - hover preview state (context): items ≤ max(value, hoveredValue) render filled; container `onMouseLeave` clears. No hover styling when `readOnly`/`disabled`.
  - `children` override → compound mode with `RatingItem` (custom icons)
- **`RatingItem`** — wraps `Radio` with required `value: number`; default content `StarIcon`, filled state via `data-[fill=true]` → `fill-primary stroke-primary` classes on the svg (p-input-10's `data-[favorite=true]:fill-primary` precedent), empty = muted outline; `data-slot="rating-item"`; reports hover via `onMouseEnter`.
- Context is private + error-throwing hook only if needed internally (no exported hook in v1).
- Non-goals (documented in Notes): half-star precision (no half-fill technique exists in the repo), custom character via `icon` prop (use compound mode), RTL beyond Base UI defaults.
